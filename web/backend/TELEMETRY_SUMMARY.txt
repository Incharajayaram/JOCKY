API ENDPOINTS:
=============================================================================

1. POST /api/telemetry/report
   Submit telemetry event from agent/binary
   Request:
     {
       "timestamp": "2024-10-10T12:34:56Z",
       "chain_id": "chain_abc123",
       "event_type": "phase_start",
       "phase": 1,
       "status": "running",
       "details": {"module": "recon", "target": "192.168.1.0/24"}
     }
   Response: TelemetryEventResponse (stored and cached)

2. GET /api/telemetry/chain/{chain_id}?limit=50
   Retrieve full execution timeline
   Response: TelemetryChainTimeline with events in chronological order

3. GET /api/telemetry/summary?chain_id=...
   Get aggregated statistics
   Response: TelemetrySummary with:
     - current_phase (highest phase seen)
     - phases_completed (count)
     - drivers_attempted / successful (counts)
     - data_collected_bytes (sum)
     - exfil_success_rate (percentage)
     - execution_time_seconds (duration)

4. WS /ws/telemetry/{chain_id}
   WebSocket live stream
   Initial message: Last 50 events as history
   Incoming messages: New events as they arrive
   Format: {"event": {...}} or {"type": "history", "events": [...]}

=============================================================================
PERFORMANCE CHARACTERISTICS:
=============================================================================

In-Memory Cache:
  - O(1) event insertion via deque append
  - 100 events max per chain (configurable)
  - No DB query needed for recent history

Database Queries:
  - O(log n) chain_id lookup via index
  - O(n) event aggregation for summary
  - Automatic cleanup every 1 hour
  - 24-hour retention policy

WebSocket Broadcasting:
  - O(c) where c = connected clients for a chain
  - Async non-blocking send to all clients
  - Automatic cleanup on disconnect
  - Connection isolation per chain_id

=============================================================================
EVENT TYPE EXAMPLES:
=============================================================================

Reconnaissance:
  - phase_start: Start reconnaissance
  - target_enum: Network scan
  - user_enum: User enumeration
  - data_collected: Data gathered

Exploitation:
  - driver_attempt: Loading BYOVD driver
  - driver_success: Driver loaded
  - driver_failed: Load failed
  - exploit_attempt: Exploit execution

Exfiltration:
  - exfil_attempt: Starting exfil
  - exfil_success: Data sent
  - exfil_failed: Blocked/failed

Evasion:
  - detection_evasion: EDR bypass
  - amsi_bypass: AMSI bypassed
  - api_hook_bypass: Hook bypassed

Errors:
  - error: Generic error
  - timeout: Operation timeout
  - permission_denied: Access denied

DATABASE SCHEMA:
=============================================================================

CREATE TABLE telemetry_events (
    id INTEGER PRIMARY KEY,
    timestamp TEXT,                    -- ISO 8601 from agent
    chain_id TEXT,                     -- Execution chain ID (indexed)
    event_type TEXT,                   -- Event classification (indexed)
    phase INTEGER,                     -- Operational phase
    status TEXT,                       -- Event status (indexed)
    details_json TEXT,                 -- JSON details
    received_at DATETIME DEFAULT CURRENT_TIMESTAMP  -- Server time (indexed)
)

Indexes: chain_id, event_type, timestamp, received_at
Retention: 24 hours (auto-cleanup)

CONFIGURATION:
=============================================================================

Cache size: 100 events per chain (configurable in app.py line 53)
Cleanup interval: 1 hour (configurable in line 62)
Retention policy: 24 hours (configurable in cleanup_old_telemetry call)
Database URL: $DATABASE_URL env var (defaults to sqlite:///./jocky_jobs.db)

To change:
  1. Cache size: Modify deque(maxlen=100) → deque(maxlen=N)
  2. Cleanup interval: Modify await asyncio.sleep(3600) → sleep(N)
  3. Retention: Modify cleanup_old_telemetry(db, hours=24) → hours=N
  4. Database: Set DATABASE_URL environment variable
